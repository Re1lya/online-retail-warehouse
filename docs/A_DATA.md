# 数据来源与ETL实现

本项目使用UCI公开的真实在线零售交易工作簿。原始文件独立保存，ODS记录每条数据的来源行号与文件校验值；清洗层保留全部源记录，以标记区分有效销售、取消交易、未知客户和疑似重复记录。销售看板统计正向销售，不将其解释为扣除取消后的净收入。

## 数据来源

- 数据集：Online Retail，创建者Daqing Chen，发布于UCI Machine Learning Repository。
- 官方页面：https://archive.ics.uci.edu/dataset/352/online%2Bretail
- 官方下载：https://archive.ics.uci.edu/static/public/352/online+retail.zip
- 引用：Chen, D. (2015). Online Retail [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C5BW33.
- 许可：CC BY 4.0，https://creativecommons.org/licenses/by/4.0/ 。本项目保留数据作者与来源署名。
- 业务背景：英国非实体店在线零售商，主营礼品，客户中包含批发商。数据覆盖2010年12月1日至2011年12月9日，不能将全部客户都视为个人消费者。
- 原始文件：`data/raw/Online Retail.xlsx`。下载时间、字节数和SHA256见同目录的`SOURCE.json`。

## 源字段

| 源字段 | ODS字段 | 含义 | 清洗层类型 |
| --- | --- | --- | --- |
| InvoiceNo | invoice_no | 单据编号，以C开头表示取消 | VARCHAR |
| StockCode | stock_code | 商品或业务项目编码 | VARCHAR |
| Description | description | 商品或项目描述 | VARCHAR |
| Quantity | quantity | 明细数量，可能为负 | BIGINT |
| InvoiceDate | invoice_date | 来源交易日期与时间 | TIMESTAMP，命名invoice_ts |
| UnitPrice | unit_price | 单价，货币为英镑 | DECIMAL(18,4) |
| CustomerID | customer_id | 客户编号，可能缺失 | VARCHAR |
| Country | country | 来源记录中的客户国家 | VARCHAR |

ODS还增加`source_row_number`、`source_file`、`source_sha256`。`source_row_number`从2开始，对应Excel中表头后的首条数据。原始8字段在ODS按文本保存，不在导入时去空白或替换异常；二进制Excel是精确原始证据。清洗后的单价保留4位小数。来源未声明时区，项目不擅自转换时区。

## ETL步骤

1. `src/download_data.py`下载官方ZIP，只读取已知的Excel成员，写入原始目录并生成来源元数据。原始文件存在时先验证SHA256，不重复下载。
2. `src/ingest.py`读取首个工作表，校验8个字段，将所有记录写入`ods.retail_raw`。重复运行完整重建ODS，避免追加产生重复导入。
3. `sql/10_clean.sql`去除标识字段两端空白，空串转换为NULL，数量进行整数有效性检查，日期使用`TRY_CAST`，单价转换为定点小数。
4. 创建`stg.clean_transactions`，记录取消标记、正向销售标记和完全重复后续行标记。此层不删除记录，由后续DWD保存全部事实、ADS按业务口径筛选。
5. `src/quality.py`扫描数据质量，返回行数、缺失、异常、取消及疑似重复计数，由主流水线输出JSON。

## 清洗与业务规则

| 情形 | 处理方式 | 对看板的影响 |
| --- | --- | --- |
| 单据以C开头，忽略大小写 | `is_cancelled=true`，保留记录 | 不计入正向销售 |
| 数量非正、单价非正 | 保留并计入质量统计 | 不计入正向销售 |
| 单据或商品为空、时间无效 | 保留记录，关联未知维度或NULL | 不计入正向销售 |
| 客户编号缺失 | 保持NULL，由客户维度映射到未知成员 | 正常交易仍计销售额、订单与件数；客户数和客户排行排除 |
| 国家缺失 | 统一为“未知国家” | 可以独立筛选，不删除交易 |
| 商品描述缺失 | 保持NULL | 编码有效的交易仍可分析，商品维度负责显示名称 |
| 原始8字段完全相同 | 以来源行号排序，首条之后标记`is_exact_duplicate` | 默认保留在统计中，公开说明数据局限 |

源文件没有可靠的业务明细行号，完全相同的两行既可能是重复导出，也可能是合法重复记账。本项目采用可追溯的保留策略，不未经确认删除；`source_row_number`仅用于唯一定位源记录，不是人为新增业务交易。

`is_positive_sale`要求单据和商品非空、日期有效、数量大于零、单价大于零、非取消。不同质量检查可以命中同一行，各项异常数量不能直接相加。UCI网页的缺失值概览与实际工作簿内容不一致，质量结论以实际扫描结果为准。

源数据的编码包含运费、手工记账、银行费用和坏账调整等业务项目。例如`POST`是运费，`DOT`是DOTCOM运费，`M`是手工项目，`B`是坏账调整。当前口径会保留符合条件的正向费用和调整记录，因此这里的正向销售额实质为正向交易金额，不等于纯商品销售收入。项目排行应解释为“商品或业务项目排行”；没有业务方确认的项目分类规则时，不根据编码外观武断删除记录。

## 交接与验收

A交给B的是`stg.clean_transactions`及质量统计，B可以按来源行号回查ODS。A交给C的是有效销售规则和异常口径，C据此设计指标。运行完整流水线后，ODS、STG与DWD行数应一致，所有来源行号唯一；正向销售记录中不能存在取消、数量非正、单价非正或必需字段缺失的行。

具体实测结果见`data/exports/a_data_verification.json`和主流水线生成的数据质量报告。原始文件为真实交易数据；所有清洗和分层派生操作都由项目源码实现。

## 大额交易与取消记录核查

商品或项目`23843`在来源中只有两条记录，描述均为`PAPER CRAFT , LITTLE BIRDIE`。通过只读查询最终数仓，并按来源行号回查ODS，得到以下证据。

| Excel行号 | 单据 | 时间 | 客户 | 数量 | 单价GBP | 带符号金额GBP |
| --- | --- | --- | --- | ---: | ---: | ---: |
| 540423 | 581483 | 2011-12-09 09:15 | 16446 | 80,995 | 2.08 | 168,469.6000 |
| 540424 | C581484 | 2011-12-09 09:27 | 16446 | -80,995 | 2.08 | -168,469.6000 |

两行的商品、客户、国家和单价相同，数量互为相反数，时间间隔12分钟。`C581484`按照数据字典属于取消记录；两行带符号金额相加为零。它们高度相关，适合作为业务异常核查案例，但数据没有提供取消单指向原单的显式外键，也没有支付或发货状态，因此不能仅凭字段匹配确认实际履约、退款到账或单据一一对应。

既定指标口径会计入第一行168,469.60英镑，排除第二行负值。这意味着商品排行中的大额表现不能直接解释为已经实现的收入或持续热销。分析结论应指出“单笔大额正向交易伴随高度相关取消记录，需业务复核”。本次核查没有改变筛选规则。查询SQL、原始来源校验值、两条记录和可复算金额保存在`data/exports/business_caveats.json`。
