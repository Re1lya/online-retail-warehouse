# 需求分析与指标体系

项目面向在线零售企业的运营、商品、市场和客户分析。我们使用 UCI Online Retail 历史数据，统一交易口径，比较销售与取消记录，查看时间趋势、商品贡献和国家分布。

## 业务问题与验收

| 分析问题 | 功能 | 验收依据 |
|---|---|---|
| 交易规模与变化如何 | 五项销售指标，年/月/日趋势 | 与原始 ODS 独立核算一致 |
| 取消对交易金额有何影响 | 取消金额、单据数、净交易记录金额、取消金额占比 | 正向金额减取消金额等于净额 |
| 哪些商品或业务项目贡献较高 | 金额 Top 10 与数量明细 | 与商品主题汇总一致 |
| 国家和客户结构如何 | 国家排行、已知客户排行 | 国家筛选影响所有页面，未知客户不进入客户数 |
| 不同维度如何组合比较 | 月份×国家×交易类型 CUBE、时间 ROLLUP、交叉表 | 每个层级与明细重新聚合一致 |
| 数据能否追溯和重建 | 来源哈希、dbt 依赖、质量测试和 CSV | 来源行守恒，校验失败保留旧库 |

## 指标口径

有效销售：单据、商品编号和日期有效，数量与单价大于零，单据不以 C 开头。有效取消：单据以 C 开头、商品编号及日期有效、数量小于零且单价大于零。两类记录均保留原始重复行，金额单位 GBP。

| 主题 | 指标 | 公式与汇总规则 |
|---|---|---|
| 规模 | 正向交易金额 | 有效销售 SUM(quantity × unit_price) |
| 规模 | 销售订单数 | 有效销售 InvoiceNo 去重 |
| 规模 | 记录数量合计 | 有效销售 SUM(quantity)，含非实物业务项目 |
| 客户 | 已知购买客户数 | 有效销售已知 CustomerID 去重 |
| 效率 | 平均订单金额 | 正向金额 / 销售订单数，无订单时界面显示 0 |
| 取消 | 取消记录金额 | 有效取消带符号金额之和取相反数 |
| 取消 | 取消单据数 | 有效取消 InvoiceNo 去重 |
| 净额 | 净交易记录金额 | 正向交易金额 − 取消记录金额 |
| 取消 | 取消金额占比 | 取消金额 / 正向金额；分母为零时为空 |

金额按记录发生日期汇总。取消可能与原销售不在同一期间，金额占比不是同批订单退货率；净交易记录金额不等同于会计收入。源数据没有取消与原订单的可靠关联、成本或履约状态。

金额与数量可加，订单数与客户数需在当前范围内重新去重，平均值和比例由汇总后的分子分母计算。日期区间包含两端；国家留空表示全部国家。缺失客户的有效交易计入金额与单据数。

## 数据与实现范围

保留全部原始行，完全重复的后续行加质量标记。商品描述取最新非空值；国家保留在每条事实上；客户首次、末次日期由当前快照计算。系统通过 Python 接入数据，dbt-duckdb 构建分层表与测试，DuckDB 存储和查询，Streamlit / Plotly 展示。模块接口见 [分工与接口](TEAM_CONTRACT.md)。
