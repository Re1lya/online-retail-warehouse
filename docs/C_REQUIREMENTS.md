# 需求分析与指标定义

## 项目背景与目标
面向在线零售企业的运营负责人、商品负责人和市场负责人，以历史交易明细建立可追溯的离线数据仓库。业务目标是统一销售统计口径，识别时间趋势、商品贡献和国家市场分布，并支持客户消费分析。项目以UCI Online Retail历史数据为例，分析结果仅描述该企业在该时间段的记录，不代表当前市场。

## 业务问题与验收标准
| 编号 | 使用者与问题 | 功能 | 验收依据 |
|---|---|---|---|
| R01 | 运营负责人查看销售规模 | 5个指标卡，日期和国家切片 | 与ODS独立核算一致 |
| R02 | 运营负责人比较时间趋势 | 年/月/日上卷和下钻 | 同一筛选范围销售额一致，订单重新去重 |
| R03 | 商品负责人识别高贡献商品 | 销售额Top10、件数、商品描述 | 与商品汇总层一致，排序明确 |
| R04 | 市场负责人比较国家市场 | 国家销售额与订单数 | 国家筛选影响全部结果 |
| R05 | 客户运营识别高消费客户 | 已知客户Top10 | 未知客户不参与排行，销售概览仍保留其金额 |
| R06 | 项目维护者检查处理质量 | 来源、质量报告、分层表、校验记录 | 原始文件有哈希，ODS/DWD行数守恒，校验失败拒绝替换旧库 |
| R07 | 答辩演示人员导出结果 | CSV下载和本地启动 | 中文Excel兼容UTF-8 BOM；按当前筛选导出 |

## 业务边界
一个业务过程：零售交易。一个事实粒度：原始工作簿的一条交易明细行。四个分析维度：日期、商品、客户、国家。InvoiceNo是单据编号，项目将正向销售中的去重单据数称为“订单数”，不是独立订单管理系统认证的履约订单数。

覆盖离线全量重建、维度建模、分层汇总和浏览器分析。成本、库存、流量、广告、支付状态和履约状态不在源数据中，因此不计算利润率、转化率、广告ROI、库存周转率或已支付GMV。没有省市与商品类别字段，不虚构地理层级或商品分类。

## 统一统计口径
有效正向销售：单据编号和商品编号非空；时间有效；数量>0；单价>0；单据编号不以C开头（忽略大小写）。金额单位GBP。源记录包含商品、邮资、手工记账及调整项目；记录数量合计不代表纯实物销量。正向交易金额不是扣除取消记录后的净销售额或会计收入。

| 指标 | 公式 | 可加性与处理 |
|---|---|---|
| 正向交易金额 | SUM(quantity × unit_price) | 可按日期、商品、国家汇总；底层DECIMAL保留4位，展示2位 |
| 销售订单数 | COUNT(DISTINCT invoice_no) | 不可直接累加日/商品/国家去重数，按当前范围重新去重 |
| 记录数量合计 | SUM(quantity) | 正向销售行的数量求和 |
| 购买客户数 | COUNT(DISTINCT known customer_id) | 排除未知客户，不累加每日去重数 |
| 平均订单金额 | 正向交易金额/销售订单数 | 先算分子分母再相除；无订单时界面显示0并提示无结果 |

国家字段按源交易记录关联，不固定在客户维度。日期边界两端包含；源时间没有时区，保留业务原始时间，不擅自转换为上海时间。看板为数据覆盖范围内查询。国家空列表表示所有国家。

## 数据质量决策
保留全部原始行，stg规范类型与空值，dwd以来源行号追溯。C开头的取消、负数量、零价与其他异常不进入正向销售，但保留供审计。未知客户的有效交易计入销售总额、订单数、件数，不计入客户数和客户排行。

对源8字段完全重复的第2条起标记is_exact_duplicate；因缺少真实业务明细行号，不能区分合法相同行与重复导出，因此基准指标保留这些行，并在质量报告显示潜在影响。不得把这些重复标记悄悄当作已确认错误删除。SQL和实际报告必须采用同一口径。

## 非功能需求与验收
本地运行，Python脚本完成ETL，SQL表达模型和指标，界面只读数据库。数据库临时构建并通过校验后替换，重跑结果应一致；SQL筛选参数化；未知维度键0避免事实行丢失。项目不要求多用户并发写入或在线更新，运行ETL前关闭看板；完成后重新打开。代码、依赖版本、原始数据、生成库、分析导出和检查结果一起交付，支持离线复核。

## 团队分工与交接
A负责数据来源、ODS与清洗；B负责四维星型模型与DWD；C负责需求、指标、DWS/ADS与正确性验证；D负责三页看板和演示。每个角色交付代码与解释文档，共用TEAM_CONTRACT.md。项目中的A/B/C/D为模拟角色，实际提交时由真实组员填写姓名学号，并理解本人负责模块。
