# 可视化与演示说明

## 成员D的交付范围

成员D负责本地Streamlit应用、三个分析页面、筛选与下载交互、录屏脚本及可视化模块说明。业务指标通过成员C提供的 `src/analytics.py` 统一读取；应用只读打开数仓，不向数据库写入。

## 启动步骤

在项目根目录打开终端，按README安装依赖并运行完整流水线。数据库默认位于 `data/warehouse/retail.duckdb`。

```bash
python pipeline.py
python -m streamlit run app.py
```

应用打开后默认显示全部日期、全部国家；国家筛选留空表示全部。选择日期区间后，五个指标与三个页面同时更新。趋势可切换年、月、日粒度。

如需指定数据库，可通过环境变量 `RETAIL_DB_PATH` 指定已有数据库路径。数据库必须包含该项目约定的ODS、DIM、DWD、DWS、ADS结构。

## 页面与业务问题

| 页面 | 业务问题 | 展示内容 |
|---|---|---|
| 销售概览 | 销售规模多大，随时间如何变化？ | 正向交易金额、订单数、记录数量合计、客户数、平均订单金额、时间趋势 |
| 商品与业务项目 | 哪些商品或业务项目贡献交易金额最多？ | 商品与业务项目金额Top 10、记录数量及明细表 |
| 国家与客户 | 哪些市场和客户贡献较高？ | 国家交易金额排行、有效客户交易金额Top 10 |

各页面支持对应结果的CSV下载；销售概览的“指标口径与数据质量”区域可下载流水线生成的数据质量报告。

## 多维分析操作

1. **切片**：选择一个国家，查看该市场的全部指标。
2. **切块**：同时选择多个国家及一个日期区间，限定分析子集。
3. **上卷与下钻**：在“趋势粒度”中切换年、月、日，观察总体及细节变化。
4. **排序**：查看按交易金额排序的商品与业务项目、国家和客户排行。

日期筛选两端包含，所有图表使用同一筛选条件。国家与客户按交易记录关联，客户维度不假定一个客户永远对应一个国家。

## 三分钟演示脚本

| 时间 | 操作 | 讲解要点 |
|---|---|---|
| 0:00–0:25 | 展示流水线成功日志、分层表与验证结果 | 数据来自UCI真实零售交易；本项目完整实现离线分层数仓 |
| 0:25–0:55 | 打开销售概览，展示五个指标和月度趋势 | 说明金额为英镑、正向交易口径、订单与客户去重 |
| 0:55–1:20 | 选择一个完整月份及一个国家，再切换日粒度 | 演示切片、切块与时间下钻，解释指标同步变化 |
| 1:20–1:45 | 切到商品与业务项目，查看Top 10并下载CSV | 识别高贡献商品与业务项目，结合记录数量、金额及项目性质理解表现 |
| 1:45–2:10 | 恢复全部国家，切到国家与客户 | 观察市场集中程度和高贡献客户；说明未知客户排除规则 |
| 2:10–2:35 | 返回销售概览，展开口径与质量说明 | 取消记录保留但不计正向交易；重复记录标记但不盲删 |

录屏前运行流水线并等待结束。录屏过程中不重建数据库，避免同时读写冲突。对比月份应选择完整月份，2011年12月只覆盖前9天；不把下降简单解释为经营恶化。

本文件是可执行演示脚本，不代表已经录制视频。正式答辩的实际录屏应另存并按课程要求提交。

## 指标口径与交接约定

- 五项KPI统一通过 `analytics.overview()` 读取；图表分别使用 `trend()`、`products()`、`country_ranking()`、`customers()`。
- UI不累加日客户数或日订单数推导跨期去重指标；跨期去重由分析层完成。
- 金额均为GBP。正向交易金额不代表净收入、利润或含税收入。
- 未知客户的有效正向交易保留在交易金额中，未知客户不计入购买客户数和客户排行。
- 数据库修改时间作为缓存版本。重建数据库后页面刷新可读取新结果；关闭浏览器不删除数据库。
- 日期未选完整、无结果、数据库缺失或未构建时均给出明确提示。

## 实测验证

对随项目交付的真实数仓执行 `python -m pytest tests/test_app.py -q`，3项界面集成测试通过：

1. 缺失数据库时显示具体构建命令，不显示伪造指标。
2. 默认页面包含3个页签与5项KPI；选择法国、2011年1月及日粒度后，全部KPI与直接查询DWD事实表的独立SQL结果一致。
3. 无交易日期显示零值和明确说明；日期范围未选完整时提示继续选择。

全量页面实测显示正向交易金额 £10,666,684.54，销售订单数19,960，记录数量合计5,588,376，已知购买客户4,338，平均订单金额 £534.40。数据库金额保持4位小数，界面按2位小数展示。

实际排行含DOTCOM POSTAGE、POSTAGE、Manual等邮资、手工记账或调整项目，因此界面统一使用“正向交易金额”“商品与业务项目”表述；记录数量合计不代表纯实物销量。取消记录未冲抵，这些指标不代表净收入或净销售。
